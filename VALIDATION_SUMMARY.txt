✅ SEMANTICS CLARIFIED
───────────────────────────────────────────────────────────────────────────
  Per-Query Detection (spanchor uses this):
  • Each query classified independently: IMPROVED/REGRESSION/UNCHANGED
  • Policy threshold: max allowed drop per individual query
  • has_regression = TRUE if ANY query exceeds threshold
  • Aggregate improvements CAN'T mask individual regressions
  • Exit code reflects per-query classification

  Aggregate Metrics (computed for reporting):
  • Macro-average across all queries
  • Used for trending and analysis
  • NOT used for regression gating
  • Diagnostic only

KEY INSIGHTS
───────────────────────────────────────────────────────────────────────────
1. spanchor's per-query detection is the CORRECT design
   - Prevents aggregate "washing" of individual regressions
   - Each query quality is independently evaluated
   - Policy thresholds are per-query, not aggregate

2. Policy configuration must use per-query metric names
   - CORRECT: "recall@5" (matches per-query metric name)
   - WRONG: "mean_recall@5" (aggregate name won't match)

3. Aggregate metrics serve diagnostics, not gating
   - Use them for trending and analysis
   - They are reported for transparency
   - Never trigger the regression gate

4. Real regression was correctly detected
   - 19 queries regressed out of 100
   - Exit code 1 correctly triggered
   - No masking by improved queries
